## 1. Why v0.1.2 Exists

The frozen v0.1.1 attempt fit one non-negative, no-intercept logistic regression across heterogeneous contaminants. It failed the retained Hephaistos benchmark:

- the 495-source fit population contained 295 debris disks, 199 YSOs, and one Hephaistos source;
- the fitted `wise_offset` coefficient fell from the v0.1 initialization value of 5.0 to 0.056;
- candidates G and B changed from `discard_confounded` to `no_action`.

This was a model-structure failure, not a reason to tune the coefficient until the benchmark passed. A single global linear coefficient vector averaged across contaminant families whose observable signatures differ. The no-intercept, non-negative form also constrained every fitted logit to be non-negative, so its outputs could rank examples but could not be interpreted as calibrated contaminant probabilities.

v0.1.2 makes two registered changes:

1. It replaces the global coefficient fit with subtype-specific, properly constrained probability models plus a separate deterministic guardrail for decisive WISE photocentre offsets.
2. It replaces the incorrect binary X-ray attenuation rule with coverage- and sensitivity-aware X-ray evidence. X-ray data are diagnostic in v0.1.2 and cannot reduce an AGN or HOT DOG confounder score.

v0.1.2 does not add a new technosignature modality and makes no detection claim.

## 2. Trust Boundaries and Safety Requirements

### 2.1 Sensitive assets

- Gaia/Cosmos credentials and any future archive credentials.
- Frozen pre-registration documents and their hashes.
- Control labels, cached catalog rows, fitted-model artifacts, and provenance hashes.
- The integrity of follow-up classifications and failure records.

### 2.2 Trust boundaries

All remote catalog responses, uploaded/local tabular inputs, YAML artifacts, archive metadata, and cached files are untrusted. The boundaries are:

1. remote archive response to schema validator;
2. validated table to cache writer;
3. cache/model artifact to scorer;
4. scorer output to release artifact;
5. credential store to authenticated network client.

No catalog payload, string field, YAML value, or file path may become executable code or a shell command.

### 2.3 Mandatory implementation controls

- Project only explicitly required remote columns. Reject missing required columns, unexpected columns, duplicate source identifiers where uniqueness is required, non-finite coordinates, RA outside [0, 360), Dec outside [-90, 90], and numeric values outside registered physical/schema bounds.
- Parse YAML with `safe_load` and validate it against an explicit schema. Unknown fields fail closed.
- Bound each CLI input to 10,000 sources per invocation, each network chunk to at most 500 sources, and retained matches to at most 100 rows per source per catalog. Exceeding a bound fails the run; it does not silently truncate scientific data.
- Use HTTPS with certificate validation. No HTTP fallback is permitted.
- Never log credentials, authorization headers, raw credential files, full remote payloads, or full user-supplied rows. Source identifiers and aggregate counts are allowed.
- Credential files must be outside the repository and mode 0600 or stricter. Repository credential files are rejected.
- Write caches and model artifacts atomically via a temporary file followed by a same-filesystem rename. Partial writes are invalid.
- Every input fixture and fitted artifact records SHA-256, row count, schema version, catalog release identifier, retrieval timestamp, and generating command. Absolute workstation paths are not published.
- A model artifact is loadable only when `status: shipped`, its pre-registration SHA-256 matches this document's freeze record, its schema is exact, and all named components match the runtime's expected component set. Failed-attempt artifacts are never auto-loaded.
- Network and schema errors fail closed. Coverage is `unknown`; it is never inferred as a null detection.

These requirements are release gates, not optional hardening work.

## 3. Populations and Leakage Controls

### 3.1 Quiet-negative controls

The v0.1 WISE-only quiet-negative definition remains unchanged. The frozen v0.1 cache may be used only if its recorded SHA-256 and schema validate. Family-model training folds must be source-disjoint.

### 3.2 Real contaminant families

The v0.1.1 attempt's retained real contaminants are reorganized by label rather than pooled into one positive class:

| Family | Initial real positives | Purpose |
|---|---:|---|
| `yso` | 199 Marton et al. sources after the frozen coverage filter | Learn YSO-like confounding |
| `debris_disk` | 295 Chen et al. sources after the frozen coverage filter | Learn circumstellar-dust confounding |
| `background_agn` | Any independently confirmed background AGN/blend cases excluding all seven Hephaistos benchmark sources | Learn background-source confounding if sample size permits |
| `catalog_blend` | Independently labeled WISE blends excluding all seven Hephaistos sources | Learn confusion/offset confounding if sample size permits |

The exact final membership, exclusions, source catalog versions, and hashes are written to `controls/contaminant_families_v0.1.2/manifest.yaml` before fitting.

### 3.3 Held-out benchmark

All seven Hephaistos candidates remain excluded from every fitted model, feature threshold estimate, calibration set, and hyperparameter choice. Candidate G is a confirmed contamination benchmark; A and B are suspected-contamination stress tests; C–F are unresolved. The inherited WISE-offset guardrail is not claimed to be independently validated by these cases because its scale predates v0.1.2 and was already exercised against them in v0.1.

### 3.4 Synthetic data

Synthetic W1-W3 offsets at 0, 1, 3, 5, and 8 arcseconds are calibration-positive/injection-recovery data only. They may test monotonicity, threshold behavior, and recovery. They may not be included as positive rows when fitting a contaminant-family probability model.

## 4. Subtype-Specific Confounder Models

### 4.1 Model form

Each eligible contaminant family h is fit independently against quiet-negative controls:

```text
r_h(x) = sigmoid(alpha_h + beta_h . x)
```

where `alpha_h` is an unconstrained intercept and every coefficient in `beta_h` is constrained to be non-negative. Every registered feature is oriented so that a larger value means stronger confounder evidence. The `P_*` components remain bounded in [0, 1]; `E_W3` and `E_W4` are the non-negative band-level empirical evidence values registered by v0.1. Missing W4 coverage is represented by `E_W4 = 0` plus `W4_covered = 0`, not by an imputed detection.

The objective is balanced binary cross-entropy plus L2 regularization:

```text
loss_h = balanced_log_loss + (1 / (2 * C)) * ||beta_h||^2
C = 1.0
```

Implementation uses `scipy.optimize.minimize(method="L-BFGS-B")` with an unbounded intercept and `[0, +inf)` coefficient bounds. Post-fit coefficient clipping is prohibited. The optimizer must report convergence; otherwise that family model is unavailable.

No new runtime dependency is introduced.

### 4.2 Fixed feature sets

| Family | Registered features |
|---|---|
| `yso` | `E_W3`, `E_W4`, `W4_covered`, `P_lowgalb`, `P_badflag`, `P_NSS`, `P_blend` |
| `debris_disk` | `E_W3`, `E_W4`, `W4_covered`, `P_badflag`, `P_NSS`, `P_blend` |
| `background_agn` | `E_W3`, `E_W4`, `W4_covered`, `P_galaxy`, `P_QSO`, `P_blend`, base HOT DOG phenotype, `P_badflag` |
| `catalog_blend` | `P_blend`, `P_badflag`, AllWISE neighbour/mate indicators |

`P_wise_offset` is excluded from every learned family model in v0.1.2 and handled only by Section 5. X-ray features are excluded from fitted risk in v0.1.2 and handled only by Section 6.

### 4.3 Cross-validation and eligibility

- Five-fold stratified cross-validation, `random_state=0`.
- At least 30 real positive sources are required for a family model. Smaller families are marked `unavailable`; they are not padded with synthetic examples.
- Quiet-negative controls are partitioned once and the same fold assignments are reused across family models.
- Report out-of-fold ROC AUC, average precision, Brier score, prevalence-only Brier baseline, calibration intercept, and calibration slope.
- A family model is eligible for scoring only if ROC AUC is at least 0.70, average precision exceeds class prevalence, Brier score is lower than the prevalence-only baseline, every fold contains both classes, and optimization converges in all folds.
- Failed or ineligible family models contribute no probability. If their registered phenotype applies to a source, that source is routed to `needs_human_review` rather than treated as low risk.

After eligibility is determined without Hephaistos data, each eligible model is refit once on its full real-family training population plus quiet-negative controls using the same fixed settings.

### 4.4 Aggregate contaminant risk

For eligible family risks, define:

```text
P_any = max_h(r_h)
ConfounderPenalty_v0.1.2 = -log10(max(1 - P_any, 1e-6))
```

The maximum is used because contaminant families are not assumed independent. Probabilities are not summed and no noisy-OR independence claim is made.

The v0.1.2 single-modality score is:

```text
LeadScore_v0.1.2 = q_IR * E_IR - ConfounderPenalty_v0.1.2 - D
```

IR evidence calibration, quality term `q_IR`, data-quality penalty `D`, and lead-level empirical p-value/BH procedure remain as registered in v0.1.

## 5. Deterministic WISE-Offset Guardrail

Rare, decisive photocentre-offset evidence must not be diluted by unrelated contaminant families.

Using the inherited v0.1 definition:

```text
P_wise_offset = min(1, offset_arcsec / 6.0)
offset_arcsec = sqrt(delta_ra_arcsec^2 + delta_dec_arcsec^2)
```

the guardrail is:

| Condition | Required routing |
|---|---|
| Independently confirmed background source at the IR/radio centroid, not the Gaia star | `discard_confounded` |
| `P_wise_offset >= 5/6` (offset at least 5 arcseconds) | `discard_confounded` |
| `0.5 <= P_wise_offset < 5/6` (offset at least 3 but less than 5 arcseconds) | `needs_human_review` |
| Offset absent or below 3 arcseconds | No guardrail classification; learned and legacy checks continue |

An offset measurement must include method, band centroids, coordinate frame, epoch/proper-motion correction, and uncertainty/provenance. A missing offset is missing data, not zero, for target sources. The legacy quiet-negative fixture may retain zero only because its selection independently excludes WISE-confused sources; this exception must be explicit in output metadata.

## 6. X-ray Evidence Semantics

### 6.1 Scientific rule

X-ray detection does not rule out a HOT DOG or obscured AGN. Some confirmed HOT DOGs are X-ray detected, while others are undetected because of obscuration and survey depth. Therefore:

- an X-ray detection may support an AGN interpretation but can never lower `P_HOT_DOG`, `P_background_agn`, `P_any`, or the ConfounderPenalty;
- an X-ray non-detection has no meaning without verified footprint coverage and a local limiting sensitivity or exposure-derived upper limit;
- v0.1.2 stores X-ray evidence as diagnostics and does not use it in the learned or aggregate confounder risk.

The binary v0.1.1 formula `base_heuristic * (1 - X-ray_attenuation)` is retired and must not be reachable in the active runtime.

Primary rationale: Vito et al., *MNRAS* 474 (2018), 4528–4540, DOI `10.1093/mnras/stx3120`, reports both X-ray-detected and X-ray-undetected HOT DOGs and finds the population heavily obscured.

### 6.2 Frozen catalog releases

| Catalog | Frozen release / identifier | Coverage treatment |
|---|---|---|
| 2RXS | VizieR `IX/29/rass` | All-sky survey presence; local sensitivity unknown unless separately retrieved |
| XMM-Newton | 4XMM-DR14, VizieR `IX/69/xmm5dr14` | Pointed footprint; coverage requires an observation/footprint or sensitivity query, not a source match |
| eROSITA-DE | DR1, VizieR `J/A+A/682/A34/table1` | German half-sky geometry is necessary but insufficient for a quantitative null; exposure/sensitivity must be retained |
| Chandra | CSC 2.0, VizieR `IX/57/csc2master` | Pointed footprint; use the official limiting-sensitivity service or equivalent footprint product |

Catalog drift is prohibited within an attempt. A newer release requires a new pre-registration or an explicitly frozen v0.1.2.x superseding document.

### 6.3 Per-catalog output schema

For each catalog, store:

- `catalog_release`
- `footprint_state`: `outside`, `inside_limit_known`, or `inside_limit_unknown`
- `local_flux_limit` and energy band, nullable only when state is not `inside_limit_known`
- `match_count`
- `nearest_match_arcsec`
- catalog positional uncertainty
- `association_probability` or `association_quality: uncalibrated`
- measured flux, flux uncertainty, hardness information, and catalog quality flags when detected

`xray_coverage_count` may be reported as a summary, but scoring and scientific interpretation use the per-catalog states. A source match may imply the position was covered; absence of a match never implies absence of coverage.

### 6.4 Positional association

When both positional uncertainties are available, the candidate radius is:

```text
r_match = min(30 arcsec, max(3 arcsec, 3 * sqrt(sigma_gaia^2 + sigma_xray^2)))
```

When the X-ray catalog lacks a usable positional uncertainty, a 10-arcsecond discovery radius may be used, but the association is labeled `uncalibrated` and cannot alter a follow-up class.

## 7. Follow-Up Classification

Apply rules in this order:

1. `discard_confounded` for confirmed background association or the high WISE-offset guardrail.
2. `needs_human_review` for the moderate WISE-offset guardrail, `P_any >= 0.80`, or an applicable confounder family whose model is unavailable/ineligible.
3. `ir_followup` only when all of the following hold:
   - `LeadScore_v0.1.2 >= 3.0`;
   - `P_any < 0.20`;
   - no guardrail fired;
   - no applicable family model is unavailable;
   - `fdr_q_value_within_coverage_class <= 0.05`.
4. `no_action` otherwise.

X-ray evidence cannot independently promote a source or turn a confounded source into `no_action`/`ir_followup` in v0.1.2.

## 8. Pass Criteria

v0.1.2 ships only if all criteria pass:

1. **Retained Hephaistos gate:** G is `discard_confounded`; B is `discard_confounded` or `needs_human_review`; A is not `ir_followup`; C–F are not `ir_followup` without the inherited manual-inspection requirements.
2. **Family-model validity:** every model marked eligible satisfies all Section 4.3 metrics using out-of-fold predictions. At least the `yso` and `debris_disk` models must be eligible. Any smaller family remains explicitly unavailable.
3. **No benchmark leakage:** a machine-verifiable source-ID intersection between every model-training table and the seven Hephaistos sources is empty.
4. **Offset guardrail:** synthetic offsets produce monotonic `P_wise_offset`; 5- and 8-arcsecond injections route to `discard_confounded`; 3-arcsecond injections route to `needs_human_review`; synthetic rows never appear in fitted-model manifests.
5. **X-ray monotonic safety:** adding an X-ray detection to an otherwise identical row never decreases any AGN/HOT-DOG confounder component, aggregate risk, or penalty. The active runtime contains no X-ray attenuation branch.
6. **Coverage semantics:** tests demonstrate all three states (`outside`, `inside_limit_known`, `inside_limit_unknown`); an in-footprint non-match remains covered; an out-of-footprint non-match remains uncovered; a catalog match is not used as the general footprint test.
7. **v0.1 secondary gates:** injection recovery remains monotonic with at least 90% recovery at 20 sigma, and held-out-null BH rejections do not exceed the registered bound at q=0.05.
8. **Input/security gates:** malformed schemas, extra fields, non-finite coordinates, excessive row counts, invalid artifact status/hash, and repository-local credential files are rejected by negative tests. No secret value appears in captured logs or exceptions.
9. **Reproducibility:** two runs over identical frozen inputs produce byte-identical model parameters, classifications, metrics, and manifests after excluding explicitly documented retrieval timestamps.
10. **Static and test gates:** unit/integration tests, Ruff, mypy under the repository configuration, and artifact-hash verification all pass.

Failure of any criterion means v0.1.2 does not ship. Record the failure under `pre_registration/failed_attempts/`; do not weaken this document.
